# Помощник агронома

Веб-приложение для экспериментального распознавания состояния листа по фотографии. Растение и состояние определяются автоматически; анализ выполняется на устройстве пользователя через DINOv2-small и ONNX Runtime Web.

**Приложение:** [agro-pomoshchnik.vercel.app](https://agro-pomoshchnik.vercel.app/) · **Рабочая ветка:** [codex/dinov2-recognition](https://github.com/NikitaUwu/agro-helper-test/tree/codex/dinov2-recognition)

Документация описывает состояние этой ветки на 23 октября 2026 года. Деплой привязан к ней; содержимое других веток может отличаться.

## Возможности

- Загрузка фотографии или съёмка через камеру, без предварительного выбора культуры.
- Реальный локальный анализ ONNX INT8 в Web Worker. Пользовательская фотография не отправляется API распознавания.
- Пять культур и 21 распознаваемое состояние, включая листья без характерных поражений.
- Справочник: пять культур, 24 карточки, поиск, фильтры, симптомы и рекомендации.
- Полевой журнал с миниатюрами фотографий и происхождением результата.
- Отказ при недостаточном score, неоднозначности, неподдерживаемом классе или низком сходстве с известными признаками.

| Культура | Распознаваемые состояния, включая здоровый лист | Карточки справочника |
|---|---:|---:|
| Томат | 10 | 10 |
| Картофель | 3 | 5 |
| Яблоня | 4 | 5 |
| Сладкий перец | 2 | 2 |
| Земляника | 2 | 2 |
| **Всего** | **21** | **24** |

Полный список состояний и причины различия между справочником и моделью: [распознавание](docs/recognition.md).

## Быстрый запуск сайта

Нужны Git, Node.js 24.x и npm. Версия 24.x рекомендуется для совпадения с Vercel; Python, серверная БД и GPU для сайта не нужны.

```powershell
git clone --branch codex/dinov2-recognition https://github.com/NikitaUwu/agro-helper-test.git
cd agro-helper-test/frontend
npm ci
npm run prepare:model
npm run dev
```

Открыть [localhost:3000](http://localhost:3000). Для установки зависимостей нужен интернет. Подготовка модели использует файлы из репозитория, проверяет их контрольные суммы и при отсутствии скачивает зафиксированные версии.

Сборка для запуска без dev-сервера:

```powershell
npm run build
npm run start -- --hostname 127.0.0.1 --port 3001
```

Открыть [127.0.0.1:3001](http://127.0.0.1:3001). Dev-сервер и production-сборку в одной папке одновременно не запускать: оба используют `.next`.

Подробности, npm-команды и устранение ошибок: [frontend/README.md](frontend/README.md).

## Где хранятся данные

| Данные | Хранилище |
|---|---|
| Справочник и соответствие классов | TypeScript/JSON в `frontend/src/data/` и `config/` |
| Фото справочника, ONNX, WASM | Статические файлы в `frontend/public/`, публикуемые на Vercel |
| Журнал пользователя и миниатюры | `localStorage` его браузера |
| Кэш модельных файлов | Cache Storage браузера; работа без кэша допускается |
| Отдельная база импорта фотографий | SQLite, по умолчанию `data/plantdb.sqlite3` |

**Сайт не подключён к SQLite.** В репозитории есть отдельный Python-пакет `plantdb` для каталога, загрузки и импорта изображений. Его установка нужна только для работы с фотобазой: [src/plantdb/README.md](src/plantdb/README.md).

Журнал не синхронизируется между устройствами, браузерами и доменами. На новом домене `agro-pomoshchnik.vercel.app` журнал со старой preview-ссылки автоматически не появляется.

## Структура репозитория

```text
frontend/                 Next.js-приложение, браузерный анализ, UI, тесты
  src/components/         Диагностика, справочник, журнал
  src/lib/diagnosis/      Подготовка фото, Worker client, политика результата
  public/                 Фото, модель, WASM, Worker
config/                   Общие JSON-реестры; исторические YAML-политики
src/plantdb/              Отдельный Python CLI и SQLAlchemy-модели
migrations/               Alembic-миграция четырёх таблиц
tests/                    Python-тесты
docs/                     Руководства, архитектура, отчёты и исторические планы
data/                     Локальная БД, загрузки, снимки benchmark; исключены из Git
PROJECT.md                Подробная техническая сводка внедрения
```

## Проверки

Из `frontend/`:

```powershell
npm test
npm run test:unit
node --test tests/model-package.test.mjs
npx tsc --noEmit
npm run build
```

Для браузерных тестов дополнительно установить Chromium:

```powershell
npx playwright install chromium
npm run test:e2e
```

Playwright автоматически запускает dev-сервер, если не задан `PLAYWRIGHT_BASE_URL`. Проверки production-сборки, Python-тесты и benchmark описаны в [руководстве по тестированию](docs/testing.md).

## Качество и ограничения

Анализ экспериментальный: score модели не является измеренной вероятностью правильного диагноза. Модель обучена на PlantVillage, преимущественно на фотографиях отдельных листьев в контролируемых условиях. Неизвестная болезнь может быть ошибочно принята за известную даже при высоком score. Результат «лист без характерных поражений» не подтверждает здоровье всего растения и отсутствие скрытых инфекций.

В [историческом тесте 21.10.2026](docs/evaluations/2026-10-21-dinov2-benchmark.md) глобальный top-1 составил 313/315, среднее время тёплого pipeline — 388,53 мс на desktop Chromium. Это измерения политики **v1** на PlantVillage с возможным пересечением с обучением. Текущая политика **v2** определяет культуру автоматически; опубликованный benchmark на 315 снимках для неё повторно не выполнялся. Полевую точность и скорость на смартфонах эти числа не описывают.

Модель/Space распространяются с CC BY-SA 4.0, ONNX Runtime — с MIT. Источники фотографий и ограничения коммерческого выпуска описаны в [документе о данных и лицензиях](docs/data-and-licenses.md). У части старых фото справочника происхождение требует подтверждения. Единой лицензии на весь код проекта в корне пока нет.
