# Данные, происхождение и лицензии

Документ описывает поставляемые артефакты и ограничения их проверки. Наличие файла в Git или записи `approved` в реестре не подтверждает права на произвольное фото с того же сайта.

## Карта хранилищ

| Слой | Место | Что сохраняется | Попадает в Git |
|---|---|---|---|
| Общий реестр | `config/model_labels.json` | 38 выходов, 21 включённый класс | Да |
| Справочник | `frontend/src/data/`, `config/model_conditions.json` | Карточки, метаданные культур, пути фото | Да |

| Модель | `frontend/public/models/`, `frontend/public/ort/` | ONNX, центроиды, metadata, WASM, notices | Да |
| Журнал | `localStorage` браузера | Пользовательские записи и JPEG-миниатюры | Нет |
| Model cache | Cache Storage браузера | Проверенные модельные ресурсы | Нет |

Локальная папка `Фото для ручного теста/`, созданная по запросу пользователя, не включена в документационный коммит. Получить исходные 315 фото в новой копии можно через [подготовку benchmark](testing.md).

## Пользовательские фотографии

При анализе исходник находится в памяти страницы. Полный preview использует временный `blob:` URL. Для журнала создаётся JPEG с максимальной стороной до 640 px и объёмом до 80 КиБ; при необходимости размер уменьшается. Миниатюра хранится как data URL в JSON `localStorage`, поэтому сериализованный объём больше бинарного JPEG.

Ключ хранилища — `agronomist_field_journal_v1`, версия записи — 2. Происхождение: `model_upload`, `model_sample`, `catalog`, `legacy_demo`. Реальная модельная запись содержит score и версии. Старые демонстрационные проценты не используются как score.

Запись результата и очистка журнала зависят от доступности и квоты браузерного хранилища. При ошибке UI сообщает, что изменение не сохранено. Экспорт/импорт журнала и облачная синхронизация пока не реализованы. Для ручной резервной копии можно сохранить значение ключа через DevTools; штатной кнопки восстановления такой копии нет.

История привязана к origin: HTTPS-домены preview и `agro-pomoshchnik.vercel.app` имеют разные хранилища. Переименование/добавление домена не переносит старые записи.

## Источники фотографий

### Зафиксированная выборка PlantVillage

У 315 benchmark-снимков и дополнительной DINOv2-галереи зафиксированы URL, исходное имя, SHA-256, Git blob SHA и ревизия репозитория `7f7ecc7e1eaca78107e3affe7cb5abd9427e139a`.

- Manifest: [2026-10-21-plantvillage-manifest.json](evaluations/2026-10-21-plantvillage-manifest.json).
- Атрибуция галереи: [dinov2-attribution.json](../frontend/public/data/dinov2-attribution.json).
- Исходный набор: [PlantVillage Dataset](https://github.com/spMohanty/PlantVillage-Dataset/tree/7f7ecc7e1eaca78107e3affe7cb5abd9427e139a/raw/color).
- Авторы: David P. Hughes и Marcel Salathé.
- Лицензия, зафиксированная в manifest: CC BY-SA 3.0.

Это контролируемый набор снимков, а не подтверждение полевой точности. Принадлежность конкретных фото авторскому train/test неизвестна, пересечение с обучением возможно.

### Старые фото справочника

Для части изображений `frontend/public/data/catalog/` происхождение и права требуют дополнительного подтверждения. Историческая пометка `hasRealPhotos` описывает наличие фото, а не юридическую проверку. До коммерческого выпуска нужны исходные URL, авторство, условия использования каждого актива либо замена на проверенные снимки.

Не все картинки в `public/data/plantvillage/` и `public/samples/` автоматически покрываются новым `dinov2-attribution.json`: он относится к перечисленным в нём файлам. Для остальных сохраняется обязанность проверить происхождение отдельно.

## Реестры источников и политики

`config/source_registry.yaml`, `config/release_policy.yaml` и `config/taxonomy_seed.json` содержат материалы проектирования более полного pipeline. Текущий CLI не применяет эти YAML-политики как готовую систему допуска/экспорта.

Рабочий seed источников находится в `src/plantdb/seed.py`: `plantvillage`, `mendeley`, `eppo`. Общие записи Mendeley/EPPO не являются разрешением на каждую коллекцию Mendeley или фотографии EPPO. ID в YAML и SQL-seed отличаются; автоматической синхронизации между ними нет.

Текущие функции `rights.py` читают два булевых признака `can_display` и `can_use_for_eval`; автоматическое доказательство лицензий, экспертная проверка и контроль прав на каждый снимок не реализованы. Для наполнения базы нужно сохранять конкретный источник, автора, лицензию, дату и версию условий вне этих упрощённых признаков.

## Резервные копии

- Git сохраняет исходники, статические файлы и документированные результаты benchmark.
- SQLite и исходные импортированные фотографии сохранять отдельно; абсолютные `file_path` требуют внимания при переносе на другой компьютер.
- Копию SQLite делать при остановленных записях либо средствами SQLite backup; незавершённая транзакция и перенос только части файлов БД могут дать неполную копию.
- Журнал пользователя не входит в серверную резервную копию и не восстанавливается из Git.
- Не коммитить `.env`, токены, пользовательские снимки или локальные базы.
