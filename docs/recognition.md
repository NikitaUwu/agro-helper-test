## Требования к фотографии

- JPEG, PNG или WebP с соответствующим MIME; пустые файлы отвергаются.
- Не более 10 МиБ и 20 000 000 пикселей.
- HEIC, SVG и другие форматы не принимаются.
- Рекомендуется один лист крупным планом, в центре, на спокойном фоне, с видимыми признаками.
- Приложение не выделяет несколько растений на снимке и не выполняет детекцию объектов.

В коде frontend нет минимального разрешения 224 px: маленький снимок может быть увеличен preprocess. Для Python-импорта отдельно действует минимальная сторона 224 px по умолчанию.

## Подготовка входа

1. `createImageBitmap` с `imageOrientation: 'from-image'` учитывает ориентацию снимка.
2. Масштабирование до короткой стороны 256 px с округлением размеров.
3. Центральный crop 224×224 через Canvas; прозрачность компонуется на белый фон.
4. RGB / 255; нормализация mean `[0.485, 0.456, 0.406]`, std `[0.229, 0.224, 0.225]`.
5. Перестановка в NCHW, `Float32Array`.

Файл реализации: [preprocess.ts](../frontend/src/lib/diagnosis/preprocess.ts). Изменение интерполяции, crop или нормализации требует новой версии preprocess и проверки качества.

## Решение после inference

Softmax считается сразу по всем 38 классам. Обрезания вероятностей до выбранной культуры нет; ручного выбора культуры тоже нет. Top-3 — три глобальных кандидата модели.

Проверки выполняются в следующем порядке:

| Условие | Результат |
|---|---|
| Неверные размеры выходов, NaN/Infinity, нулевой feature vector | `error / inference_failed` |
| Максимальный cosine с центроидами `< 0.699429452419281` | `uncertain / ood` |
| Глобальный победитель выключен или не связан с карточкой/культурой | `uncertain / unsupported_class` |
| Score победителя `< 0.85` | `uncertain / low_score` |
| Разница первого и второго score `< 0.20` | `uncertain / ambiguous` |
| Все проверки пройдены | `accepted` с культурой и состоянием победителя |

Центроиды в поставляемом файле нормализованы; policy делит скалярное произведение на норму feature vector. OOD-проверка — эвристика сходства, она не гарантирует обнаружение неизвестной болезни. Запрещённый победитель не подменяется разрешённым кандидатом со второго места.

Score — значение softmax, а не полевой показатель точности. Веса, пороги и тексты должны оставаться согласованными; пороги нельзя снижать только ради уменьшения отказов на нескольких примерах.

## Программный контракт

```typescript
analyzeLeaf(
  request: { requestId: string; image: Blob; source: 'upload' | 'sample' },
  onProgress: (event: AnalysisProgress) => void,
  signal: AbortSignal,
): Promise<DiagnosisOutcome>
```

Функция экспортируется из [client.ts](../frontend/src/lib/diagnosis/client.ts), типы — из [types.ts](../frontend/src/lib/diagnosis/types.ts).

- `accepted`: `conditionId`, `cropId`, `score`, `top3`, `oodSimilarity`, версии, времена и request ID.
- `uncertain`: причина отказа, `top3`, `oodSimilarity`, версии и времена; карточка подтверждённого результата не создаётся.
- `error`: причина `invalid_file`, `decode_failed`, `model_load_failed`, `inference_failed` или `timeout`, пользовательское сообщение.
- `cancelled`: request ID отменённой задачи.

`inferenceMs` измеряет ONNX-запуск в Worker; `initializationMs` отдельно описывает создание движка. Это не всё время пользовательского сценария.

## Как изменять поддерживаемый набор

Для уже существующего класса другой культуры нужны согласованные карточки/метаданные, включение в реестре, обновление типов и списка культур, фотографии с происхождением и проверки. Один `enabled: true` не добавляет полноценную поддержку в продукт.

Для **нового состояния текущих пяти культур** понадобится другая обученная модель либо обучение новой классификационной части DINOv2 на размеченных данных. Карточка справочника и новая строка JSON не создают новый выход ONNX.

При замене модели:

1. Зафиксировать источник, ревизию, лицензию, порядок классов и preprocessing.
2. Подготовить согласованные ONNX, центроиды/метаданные и manifest с хэшами.
3. Обновить `prepare-model.mjs`, Worker, `registry.ts` и общие JSON; если меняются размеры выходов — также policy и тесты.
4. Изменить версии model/policy/preprocess в соответствии с реальным изменением.
5. Проверить Python seed/downloader, карточки, coverage, журнал и отсутствие подмены глобального ответа.
6. Выполнить unit, E2E, model-smoke и новый benchmark на выделенной проверочной выборке; сохранить прежние результаты отдельно.

Повторяемые измерения и ограничения опубликованных чисел: [testing.md](testing.md).
