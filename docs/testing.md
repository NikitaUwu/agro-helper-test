# Тестирование и измерения

## Подготовка frontend

Node.js 24.x, команды из `frontend/`:

```powershell
npm ci
npm run prepare:model
npx playwright install chromium
```

## Уровни проверок

| Команда | Покрытие | Что не доказывает |
|---|---|---|
| `npm test` | Структура каталога, доступность файлов, соответствие ID и модельных классов; на текущей версии 360 assertions | Работу интерфейса и точность модели |
| `npm run test:unit` | Численная policy, отказы, отмена/ошибки клиента, совместимость и квота журнала | Реальный WASM и мобильное устройство |
| `node --test tests/model-package.test.mjs` | Хэши модельного пакета, сохранённые benchmark-входы и предсказания | Скорость, новый benchmark |
| `npm run test:e2e` | Взаимодействия UI, настоящий Canvas/WASM, реальная загрузка фото, журнал, ошибки и responsive | Независимую полевую точность |
| `npm run test:model` | Node-проверки пакета и отдельный Playwright model-smoke | Остальные UI-сценарии |
| `npx tsc --noEmit` | Согласованность типов TypeScript | Корректность данных во время исполнения |
| `npm run build` | Production-сборка и подготовка ресурсов | Полное прохождение пользовательского сценария |

`npm test` не является umbrella-командой остальных тестов. `npm run lint` пока не считать обязательной автоматической проверкой: ESLint-конфигурация не заведена и Next.js может предложить интерактивную настройку.

Быстрая последовательность без браузера:

```powershell
npm test
npm run test:unit
node --test tests/model-package.test.mjs
npx tsc --noEmit
```

## Браузерные проверки

По умолчанию `npm run test:e2e` запускает Next.js dev на `127.0.0.1:3000` либо использует уже доступный сервер на этом адресе. Для предсказуемой проверки production:

Терминал 1, из `frontend/`, после остановки dev-сервера:

```powershell
npm run build
npm run start -- --hostname 127.0.0.1 --port 3001
```

Терминал 2, также из `frontend/`:

```powershell
$env:PLAYWRIGHT_BASE_URL = 'http://127.0.0.1:3001'
npm run test:e2e
Remove-Item Env:PLAYWRIGHT_BASE_URL
```

В bash эквивалент задания переменной для одной команды: `PLAYWRIGHT_BASE_URL=http://127.0.0.1:3001 npm run test:e2e`.

Текущий набор содержит 15 E2E-сценариев:

- Камера/загрузка доступны без выбора культуры; анализ образца.
- Культура определяется ответом модели, даже если подпись образца относится к другой.
- Неподдерживаемый победитель даёт отказ и не создаёт запись.
- Отмена не приводит к запоздавшей карточке/сохранению.
- Реальный upload проходит локальный анализ, JPEG-миниатюра сохраняется после reload, POST-запросы не выполняются.
- Настоящий Worker выдаёт 38 logits и 768 признаков, Canvas сохраняет ожидаемые каналы/crop/нормализацию.
- Coverage соответствует реестру и не запускает загрузку модели при раскрытии.
- Справочник скрывает неподдерживаемые культуры в поиске и фильтрах.
- Legacy-записи сохраняют растение/состояние, старые проценты не выдаются за score.
- Переполнение хранилища, сетевой отказ модели, повторный выбор повреждённого JPEG и ширины 360/390/430/1280 px.

Часть UI-тестов использует управляемый mock движка, чтобы воспроизвести конкретные ошибки и проверить сохранение ответа. Реальный ONNX проверяется отдельно в model-smoke и real-upload. Число успешных тестов нельзя интерпретировать как число проверенных диагнозов.

Playwright работает с одним worker, viewport по умолчанию 390×844. При неудаче trace сохраняется в `frontend/test-results/`. Этот каталог не коммитится.

Скриншоты настоящего upload-сценария:

```powershell
$env:EVIDENCE_DIR = '../data/ui-evidence'
npm run test:e2e -- real-upload
Remove-Item Env:EVIDENCE_DIR
```

Не запускать dev и production-процессы поверх одной `.next` одновременно. 404 чанков при такой конфигурации сначала проверять как конфликт окружения.


Текущий набор — 12 тестов схемы, прав, качества, импорта и общего реестра. Для запуска без editable-install потребуется доступ к зависимостям и `PYTHONPATH=src`; рекомендуемый путь — установка `-e '.[dev]'`. Тесты не должны обращаться к рабочей фотобазе.

## Ручная проверка

1. Открыть приложение; убедиться, что культура заранее не выбирается.
2. Проверить «Что распознаёт анализ»: пять культур, 21 состояние, включая здоровые листья.
3. Загрузить известный снимок, записать определённое растение/состояние либо причину отказа. Не считать подпись образца ответом модели.
4. После принятия результата открыть журнал и перезагрузить страницу: миниатюра и происхождение должны сохраниться.
5. Открыть справочник: пять культур, 24 карточки; поиск «огур» и «пшениц» не даёт карточек.
6. Открыть справочную карточку неподдерживаемого состояния яблони/картофеля: score не появляется, автоматической записи анализа нет.
7. Проверить отмену, повторный выбор файла, повреждённый файл и отсутствие горизонтального переполнения на узком экране.

Для диагностики обобщения отдельно нужны полевые снимки и неподдерживаемые растения/болезни, посторонние объекты, несколько листьев и смешанные поражения. У высокоуверенной классификации возможен ошибочный ответ; ожидаемые диагнозы должны подтверждаться независимо от этой модели.

### Подготовить локальную папку из фиксированных снимков

Из `frontend/` восстановить фото:

```powershell
node scripts/prepare-evaluation.mjs
```

Затем из корня выполнить PowerShell-пример ниже. Он создаёт **новую** папку; существующую не перезаписывает. Состояние для сравнения берётся из метки исходного набора.

```powershell
$target = Join-Path (Get-Location) 'Фото для ручного теста'
if (Test-Path -LiteralPath $target) { throw 'Папка уже существует' }
$manifest = Get-Content docs/evaluations/2026-10-21-plantvillage-manifest.json -Raw -Encoding UTF8 | ConvertFrom-Json
$names = @{tomato='Томат'; potato='Картофель'; apple='Яблоня'; pepper='Сладкий перец'; strawberry='Земляника'}
New-Item -ItemType Directory -Path $target | Out-Null
$rows = foreach ($sample in $manifest.samples) {
    $folder = Join-Path $target $names[$sample.trueCropId]
    New-Item -ItemType Directory -Force -Path $folder | Out-Null
    Copy-Item -LiteralPath $sample.file -Destination $folder
    [pscustomobject]@{File=$sample.imageId; Plant=$names[$sample.trueCropId]; Expected=$sample.trueConditionId; Source=$sample.sourceUrl; License=$sample.license; Attribution=$sample.attribution}
}
$rows | Export-Csv (Join-Path $target 'Ожидаемые результаты.csv') -Delimiter ';' -NoTypeInformation -Encoding UTF8
```

Получится 315 фото: томат 150, картофель 45, яблоня 60, перец 30, земляника 30. Это повторение benchmark-набора с возможным пересечением с обучением, а не новая независимая выборка. Для использования/передачи фото сохранять CSV с атрибуцией.

## Повторить benchmark

Из `frontend/`, после установки зависимостей и Chromium:

```powershell
npm run prepare:model
node scripts/prepare-evaluation.mjs
npm run evaluate:model
```

Подготовка восстанавливает 315 входов и дополнительную галерею по неизменяемой ревизии PlantVillage, проверяя SHA-256 и Git blob SHA. Неверный кэш не считается готовым снимком. Benchmark запускает собственный локальный HTTP-сервер и headless Chromium; Next.js для него не требуется.

Передаются только фото и request ID; эталонные культура/состояние используются для подсчёта метрик. После отдельного холодного запуска выполняются три последовательных непересекающихся прогона по 105 файлов и пять синтетических однотонных негативов.

**Скрипт перезаписывает исторические файлы** `2026-10-21-dinov2-benchmark.json`, `2026-10-21-dinov2-predictions.json` и Markdown-отчёт в `docs/evaluations/`, а также рабочие `metrics.json`/`predictions.json` под `data/evaluations/`. Дата в имени не выбирается автоматически. Сохранять новые результаты под отдельной датой/версией перед публикацией, чтобы не потерять историческое сравнение. В этой документационной работе повторный benchmark не запускался.

Различать метрики:

- **Top-1 accuracy** — доля совпадений глобального победителя с меткой среди всех снимков, включая случаи отказа приложения.
- **Top-3 accuracy** — наличие метки среди трёх глобальных кандидатов.
- **Accepted precision** — доля верных среди принятых результатов.
- **Coverage** — доля принятых среди всех снимков.
- **Тёплое totalMs** — декодирование, preprocess, inference и policy после подготовки модели; без выбора файла, React rendering и записи журнала.
- **Cold start** — отдельный запуск с инициализацией/загрузкой по localhost; не мобильная сеть.

Измерения [21.10.2026](evaluations/2026-10-21-dinov2-benchmark.md): policy v1, top-1 313/315, mean total 388,53 мс, accepted 295/315, accepted correct 295/295. Они не были повторены для нынешней policy v2. Высокие числа на PlantVillage не подтверждают полевую точность; синтетические негативы не валидируют весь класс неизвестных болезней.
